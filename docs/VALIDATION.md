# Validation record (simulated telemetry)

Generated by `edge_intelligence/tests/test_validation_scenarios.py` (set `OPSLENS_VALIDATION_REPORT=path.json` to write the raw records). Each case injects conditions into the simulator, runs the normal backend pipeline (evidence engine → cause candidates → roles), and compares the computed leading/contributing candidates with a reference outcome written down **before** the run. The reference (`REFERENCE_OUTCOME` in `incident_catalog.py`) is read only by the test suite and the engineering Inspector; a test checks that no diagnosis, ranking or prompt code reads it, and the operator HMI never shows it.

**Limits of this validation.** All telemetry is simulated. It shows the ranking logic responds to the evidence it is given (a changed telemetry pattern changes the answer); it does not show accuracy on a real plant. Evidence points and Evidence Support are rule-based scores, not probabilities.

## Discrepancy found and how it was handled

Scenario 1 (bar screen): the original reference named the BS-2 rake motor trip as the cause. While building test D1 we found a genuine defect: the incident's "first triggered" time was the trigger timestamp, which moved when the primary alarm was reassigned, so a trip that happened *after* the primary alarm could be counted as before it. After the fix (`operator_brief.primary_alarm_first_on`), the injected timing (inflow rises ~22 s, screen differential-level alarm ~39 s, rake trip ~54 s) puts the trip after the alarm, so it cannot have started it. We corrected the **reference** to match the injected timing (inflow above one-screen capacity leads; the trip is a later condition). The ranking code was not tuned to make the test pass.
